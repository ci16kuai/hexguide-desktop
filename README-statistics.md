# 英雄与海克斯胜率统计

英雄胜率榜和单海克斯胜率差使用 [AramHex / czgreat/aramhex-data](https://github.com/czgreat/aramhex-data) 的开放汇总数据，按 **CC BY-NC 4.0** 署名、非商用使用。原许可随软件附于 `dist/licenses/aramhex-data-LICENSE.txt`，在线许可为 <https://creativecommons.org/licenses/by-nc/4.0/>。

展开后的条件装备与海克斯组合统计另从 [ARAMKit](https://aramkit.com/) 按需读取。两类来源分别保留版本、日期和统计范围，不交叉计算胜率增幅。AramHex 的开放许可仅适用于对应的 AramHex 统计，不适用于 ARAMKit 数据、Riot 游戏文本、图标或装备资料。

有效对局标准由来源确定：不少于4分钟、10名玩家完整且正好5胜5负、正常结束。重开、提前解散和不完整对局不计。

海克斯统计按**对局结束时持有**计算，同一玩家六个槽位去重。它不是每次三选一选项的随机试验；海克斯选择倾向、出现阶段、英雄阵容和其他海克斯都可能影响观察胜率。任务完成后被替换而导致局末统计失真的“尊我为王”（1337）与内部模板（3176）被来源排除，不会凭空补值。

## 转换与排名

1. 数字英雄ID通过固定的Riot Data Dragon 16.21.1目录映射为本项目英文ID，不靠中文名称模糊匹配。
2. 数字海克斯ID通过当前目录的 `gameDataId` 对应本地slug；未映射条目保留来源原名与统计，不将其冒认为其他海克斯。
3. 校验胜负场次与来源概率相符，将0～1概率转换为0～100百分数；界面计算时使用有效原始 `wins / games`，最后才格式化显示。
4. **胜率差（百分点）= 持有该海克斯样本中的英雄胜率 − 同口径该英雄整体胜率**。只有来源、模式、版本、地区、分段和统计时间一致的记录才计算。未知值保持 `null`，不会变成0%。
5. 排序使用未四舍五入的差值。负数仍显示；来源 `low_sample` 标记的低样本（少于3,000场）默认排除，可手动展开。测试服暂补、非当前目录等参考记录单独标注，不混进正式服可比排名。
6. “我的这一局”为默认首页；英雄胜率榜独立于本局状态，以完整页面宽度显示，不包含本局控制区或加入本局操作。顶部所有功能入口直接展开。

历史选择率仍来自原有 arammayhem.com 26.20 数据集，胜率榜来自此独立 AramHex 16.21 快照。两份数据不混算，原海克斯库的选择率不能当作胜率。

## ARAMKit 条件装备与组合统计

只有用户展开某英雄的统计条目时，页面才按需直连 ARAMKit 的公开 JSON：先读取 [版本清单](https://data.aramkit.com/data/versions.json)，再按所选版本的 `dataPath` 读取该英雄的两份文档：

- `stats/all/champion-details/{数字英雄ID}.json`：该英雄的统计及来源已发布的双海克斯组合。
- `stats/all/champion-details/{数字英雄ID}-single-augments.json`：该英雄持有单个海克斯时的装备、三件套和购买顺序统计。

应用在页面内存中最多缓存3位英雄，命中缓存时复用结果；不下载整库，也不把远端统计数据打包进源码或安装包。请求仅用于用户正在查看的参考数据，不上传当前对局、账号、敌方阵容或已选海克斯。

以英雄 H 和海克斯 A 为条件，展开区展示来源记录的三件套、购买顺序和单件装备，卡片只附各自胜率。样本数保留用于内部验证和排序，不在展开卡片上显示；主榜原有样本列不变，展开区的数据说明可折叠查看。三件套集合、购买路线、单件装备和不同统计范围各有自己的样本口径及选择率分母；不把不同层级的比例相加，也不与 AramHex 的英雄基线计算增幅。

共同出现海克斯仅从该英雄源文档已发布的至多10组双海克斯组合中筛选包含 A 的条目，再按共同样本数排序，卡片只附组合胜率。它表示这些已发布记录中的 H＋A＋B 组合，不是完整共同选择频率表，也不声称找到了全部数据中最相关或最常同选的 B。双海克斯组合统计和 H＋A 装备统计分别展示，不拼接成 H＋A＋B 条件下的装备胜率，也不预测本局下一轮选项。

少于200个样本时仍计算内部低样本标记，前端展开卡片不显示该标记或样本数。200不代表统计显著性或选择后的因果收益，也不替代 AramHex 榜单原有的3,000场来源筛选规则。原站提供的是聚合统计，本功能没有可逐局核实的匿名比赛记录。

请求失败、某个海克斯没有条件数据或组合未被来源发布时，明确显示暂缺；不退回机制推导、通用英雄出装、其他英雄或其他统计范围来填补。装备名称、图标和简短效果仍取自随包的 Riot 本地装备目录，保留原有触发条件与否定；统计中的 `0` 表示未购鞋。未来未收录的装备保留其ID，内部保留原始计数，不冒认为另一件装备。

## 重跑与来源保护

```powershell
node scripts/update-statistics.mjs
```

该命令用于复现随包快照：固定上述来源提交、seq及16.21正式服规则，核对源文件SHA-256、结构、胜负场次、概率、唯一ID及测试服暂补标记；全部成功后才替换 `dist/statistics.json`。支持 `--offline`、`--refresh`、`--cache` 和 `--out`；下载和临时数据默认放在H盘任务工作目录。统计发生时间始终使用来源快照时间。

运行时更新由 `server/statistics-source.mjs` 共享同一转换与校验边界：先从固定GitHub主分支引用解析40位提交，再按该提交读取清单、元数据与全体统计表。只接受与本地 `clientDataVersion` 主次版本一致的正式服常规数据；不追踪测试服、活动规则或分段表。每份表限制4MiB、清单限制64KiB，禁止跳转并设下载超时；逐流限制大小，校验清单大小和SHA-256。来源快照与表哈希未变时，只读取引用和清单；同一时间戳的修订数据仍重新校验。

AramHex没有承诺固定发布周期。应用每三天检查可以获取来源已经发布的新数据，无法生成尚未公开的新快照。三天调度、缓存替换和失败恢复由应用的统计存储模块负责；异常下载不会作为有效统计发布。

本项目对 AramHex 原数据作了ID映射、单位转换、可比性处理和展示，未改变原始胜负场次。数据署名保留AramHex及源仓库链接，适用于对应统计部分；该更新器不会下载 ARAMKit 条件统计。
