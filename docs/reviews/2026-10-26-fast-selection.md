# 1.14.0 直接选择漏记与识别延迟

用户操作：直接点击游戏三选一卡片后继续玩，不再打开六格结果面板。

## 原因与修复

- 1.13.1 在后端存在六格来源时关闭直接点击观察器，导致上述操作没有自动确认来源。现在同时接入直接点击与六格结果，两者经过同一个权威提交边界。
- 原生每两秒取完整推荐，即使 OCR 已结束仍可能晚收到候选。新增认证的轻量识别快照，观察期间目标每 150 毫秒同步；不重复计算装备和统计。完整推荐出错不撤销健康的新识别上下文。
- 旧观察器不能处理 OCR 返回前发生的点击。新增有界的原生内存证据：两帧基线、真实按下/松开和后续图像。精确标题返回后，按原始采集几何和标题锚点回放原有严格判定，仍需独有选择反馈和三帧收起；没有用消失或指针最后位置猜选。
- Windows OCR 输入由 PNG 编码、流传输和解码改为 BGRA 像素深拷贝。沿用现有缩放、串行阶段、帧身份、名称和锚点校验。

## 边界

内存上限 64 MiB / 44 帧，交互最多五秒、松开后最多 2.5 秒。上下文包含局次、会话修订、识别生命周期、采集修订与硬失效水位；签发时间与最长一秒的连续心跳限制保留期。过期响应不能续期旧证据，失焦、遮挡、重掷、人工修改、采集失败和超限清除缓存。像素不落盘、不进入诊断或本机提交载荷。

临时 OCR 空白只允许本轮已经松开的点击完成结果证明；它不生成新的点击资格，也不推进硬失效水位。直接点击与面板并发时只记录一次，忙时保留有时效的证据，面板被拒或失败会收到释放回调。

开始观察之前已经发生的选择、OCR 首次有效采集之前已关闭的卡片、遗漏的极短选择特效都不能据此恢复；仍保留手动补录与六格面板来源。生成画面和状态机测试不代表真实游戏识别已稳定。

## 性能与验证

同一已初始化 Windows OCR 引擎交替测试旧 PNG 和新 BGRA 路径，每组十个热样本，固定生成的 2560×1440 中文标题：彩色三标题阶段中位数 179.400→123.896 ms，增强对比 230.933→176.748 ms。每次都保持三个名称和三组锚点。此结果只表示生成画面的对应阶段，不能作为整次真实游戏的速度保证。三图拼接方案没有热态收益，已弃用。

独立审查发现并修正：轻量响应遗漏生命状态时间戳、旧响应回退上下文、临时空白错误推进缓冲硬水位、直接点击状态被面板状态覆盖、延迟响应和停顿后的心跳复活旧证据、忙时提前丢弃证明，以及完整推荐失败清除健康观察。最终源码复核无剩余阻断项。

1.14.0 已更新至原安装目录，83 个程序文件逐一比对摘要；在普通桌面上下文备份并核对两个已有存储视图中的设置和本局文件，安装前后保持一致，没有移动数据目录。最终由普通桌面上下文恢复后台，确认仅一个助手和一个本地服务，界面返回 1.14.0；锁文件仍位于普通用户原目录，游戏进程及创建时间保持原样。

启动后的技术诊断显示新的轻量上下文和有界缓冲已在游戏前台工作：两帧基线约 2.6 MB，观察范围心跳新鲜，采集计数正常，快捷键注册成功。这只验证新链路已启用；没有据此声称已经观察到真实快速点击、特效和已选提交的完整成功。真实选择的连续漏记率、极短特效和混合显示器 DPI 仍需实战核对。

原始离线数据与诊断位于本次 H: 工作目录，不含游戏画面或玩家身份。所有正确性和性能基准均使用生成画面或隔离状态。
