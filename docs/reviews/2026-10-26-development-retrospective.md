## 本轮修正

### 1. 补录旧轮导致当前扫描周期提前停止

触发过程：第 1 轮候选尚未确认，死亡复活后进入第 2 轮扫描，再补录第 1 轮。原先 `recordChoice()` 对任何确认都调用 `scanSchedule.confirmed()`，使第 2 轮从快速扫描转为停止，后续三卡或重掷不能自动更新。

现在先找到被确认的待确认轮次。只有该轮在当前扫描生命周期中被重新识别，或者明确已选来源没有可归属的待确认轮次，才沿用结束当前周期的行为。补录旧轮仍递增会话修订、撤销过期点击和面板证据；当前周期的标识、截止时间和后续扫描机会保留。下一次扫描需建立新证据，旧在途结果不能继续提交。

覆盖旧轮先确认、当前周期还没有新 OCR、当前周期重见同组三卡、重启恢复目录，以及先确认新轮再补旧轮。独立临时探针另核对在途 OCR 失效和慢速续扫阶段，均保持原截止时间且不重开已停止周期。

### 2. 新 OCR 已更新窗口位置，面板核对仍使用旧坐标

触发过程：同轮识别后移动游戏窗口，新的合法 OCR 捕获记录了新位置，但面板凭据只比较局次、生命周期和修订，没有比较几何信息。因此原生观察器一直收到旧位置并拒绝采集。

现在窗口句柄、客户区原点/尺寸、三卡区域和标题锚点矩形变化时，重新签发面板凭据并建立新的帧时间下限。旧凭据不能提交；新凭据需要新的独立多帧证明。只有采集时间、帧标识、像素和标题特征变化时继续复用原凭据，避免每次 OCR 都重置稳定性窗口。

回归包含六类几何变化、旧证明拒绝、新证明成功，以及同几何重复扫描不打断多帧证明。实现位于 `server/sidebar.mjs`，回归位于 `tests/panel-sidebar.test.mjs`。

### 3. 补齐可重复的开发验证入口

新增 `scripts/verify-desktop.ps1` 与 `npm run verify:windows`，串行运行预检、现有 Node 测试、独立 Windows 构建、原生选择检查、单实例检查和侧栏离屏预览。

每次建立独立运行目录，保存分步日志和 `summary.json`；失败返回非零退出码，未执行阶段保留 `not-run`。测试列表读取现有 `package.json`，只接受明确支持的 `node --test` 文件列表，不把任意包脚本交给 shell 执行。临时目录、生成图片、构建目录和缓存均可配置到 H 盘。

已验证缺少 Node、断言失败、带空格路径及不受支持的脚本结构等失败路径。该入口只运行隔离测试；不启动普通助手，不操作游戏，不读取已安装版设置。README 同时补充当前状态入口，并更正带旧版本号的构建示例。

## 主要不足与下一步验收

1. **直接点击漏记仍是优先问题。** 当选择特效已经出现在松开帧、松开时卡片已消失，或完整按下/松开落在两次轮询之间时，现有证据链可能不完整。现有日志证明某次漏记发生，但不能确定该局命中了哪条分支。后续应按有界事件时间线关联点击、参考绑定、视觉判定和服务端接受结果，再决定输入/视觉采样方案。不能把松开亮度一律当作选择特效，否则可能接纳长按 hover。证据见 [本局漏记复盘](2026-10-26-live-recognition-audit.md)。
2. **显示与识别需要分别验收。** 下一局检查其他应用获得焦点但游戏仍露出时，侧栏在 600 毫秒之后持续显示；完整遮挡、最小化与手动收起仍隐藏。OCR 与点击采集继续要求自己的前台/遮挡条件。本轮原生审查没有发现显示兼容策略放宽采集权限。
3. **“测试数量多”与“真实使用稳定”必须分开。** 当前已有较多边界回归，但最容易漏掉的是不同轮次、窗口移动和异步更新的组合。这次两个缺陷都来自组合场景。后续每个真实反馈应先整理时间线和最小可复现输入，再加入针对行为的回归；统一入口负责避免漏跑，不承担实战准确率证明。
4. **保留集中验收记录，减少版本状态漂移。** 首页此前混用了历史“尚未部署”与当前版本说明。本轮新增当前状态段并保留历史证据。后续发布时只更新明确已验证的项目，不把构建成功自动升级为实战成功。

本轮未改变三卡相同内容的去重策略，也没有新增未经校准的视觉识别规则。暂未证实的原生路径保留为明确缺口，避免以放松确认门槛换取表面成功。
