# 1.12.1 六项修复记录（2026-10-25）

当前为尚未发布的测试版源码。此次范围是修复、离线回归及构建检查；没有安装更新、重启助手或操作游戏。此前 1.11.3 的实战记录仍只证明当时观察到的行为，不能代替 1.12.1 的连续实战验收。

## 1. 同形图标与已拥有次数使用一致身份

原生曾按字形把不同 URL 的图标归为同一组，后端按 URL 分组，可能拒绝原生的完整组；已有同形图标的出现次数也需要按同一身份扣除。

面板证明升级为 v2，固定九个顶层字段：`version / provider / offerToken / gameId / gameEpoch / revision / ids / glyphs / frames`。`glyphs.algorithm` 为 `normalized28-sha256-v1`；28×28 归一化布尔字形按行打包为 98 字节后计算 SHA-256。每个模板同时携带算法、目录 ID 与 URL 的绑定摘要，顺序为三个当前候选，随后最多六个已选模板，总数最多九个。后端校验绑定、顺序和完整性，以相同字形摘要识别跨 URL 的同形组，并先扣除已拥有次数。相似但不同的字形保持不确定；同一 URL 不能声明两个不同身份。

载荷上限仍为 4 KiB，原生发送前与 HTTP 边界都检查大小。旧面板协议、缺项、错序和不一致绑定拒绝提交。摘要是本机原生分类证明，不是后端独立像素验证或密码学认证，不持久化或上传。技能强化固定图标素材仍待核实，不能据此宣称所有同形情况已可靠排除。

实现：`native/OwnedPanelWatcher.cs`、`server/panel-glyph-identity.mjs`、`server/panel-selection.mjs`。回归入口：`tests/panel-glyph-identity.test.mjs`、`tests/panel-selection.test.mjs`、`tests/panel-http.test.mjs`、`tests/panel-sidebar.test.mjs`，含固定真实目录素材与原生提取夹具。

## 2. 死亡、复活及共享扫描的生命周期守卫

识别生命周期与快速阶段时钟分离。可信死亡立即撤销旧候选、点击/特效凭据及面板资格；复活新周期、换局和明确离开本模式推进生命周期。同一组三候选在复活后再次出现，也必须重新采集和签发 token；生命周期开始前的缓存帧不能恢复旧资格。重复死亡样本不反复推进，普通失焦或未知生命状态不冒充死亡，不延长旧证据。

手动与自动请求共享一次在途 OCR，并使用相同的局次、生命周期、修订及当前实战资格完成校验。手动请求可在自动周期外启动；同周期快速→慢速切换允许任务完成，旧周期、人工纠正或明确资格失效后的迟到结果不能覆盖新状态，旧任务的完成状态也不能污染新周期节奏。

实现：`server/ocr-schedule.mjs`、`server/sidebar.mjs`。回归入口：`tests/recognition-lifecycle.test.mjs`、`tests/scan-scheduling-sidebar.test.mjs`、`tests/selection-continuation.test.mjs`。

## 3. 一个数据目录对应一个桌面实例

主程序在启动本地服务前取得指定数据目录中 `.hexguide-instance.lock` 的独占写句柄；同目录重复打开只通知既有实例恢复界面，不再启动第二套后端和采集。不同数据目录仍可独立运行。有效所有权来自打开的文件句柄，残留锁文件不会阻止退出后再次启动。目录规范化后的摘要用于同一 Windows 会话的通知窗口身份，通知不包含命令行、凭据或游戏状态。

实现：`native/ApplicationInstance.cs`、`native/Program.cs`。离线实例夹具覆盖同目录重复、不同目录、跨进程占用和释放后重开；不读取安装版个人数据。

## 4. 禁用终极技能先排除依赖项

`engine.js` 提供共享的 `noUltimate / requiresUltimate` 效果文本约束。明确禁止自身终极技能的海克斯，与收益完全依赖该技能的海克斯双向冲突；联动解释、适配评分、直接排名、三选一及实战后续推荐共用约束，在统计胜率排序前排除冲突。

规则不按英雄 ID 硬编码，也不因名称或一次终极技能提及整项禁用。基础技能、独立触发、自动借用的技能、兼有独立收益的效果及装备的独立属性保留。真实随包统计回归包含 Fiddlesticks、Karthus、Kennen：其原先可进入前六的“最终形态”“终极刷新”等不能在“回归基本功”禁用终极技能后重新进入推荐；反向选择同样受保护。

实现：`dist/engine.js`、`dist/recommendation-policy.js`，实战经现有 `adaptive.js` 调用同一引擎。回归入口：`tests/ultimate-constraints.test.mjs`、`tests/recommendation-policy.test.mjs`、`tests/adaptive.test.mjs`、`scripts/test-engine.mjs`。

## 5. 侧栏图标缓存回收与失败重试

展示图标使用最多 96 项的 LRU 内存缓存，在途下载最多 8 个，同 URL 请求去重。失败完成会释放在途名额，30 秒后允许重试；失败记录也有容量上限。淘汰、替换与关闭释放原图，关联着色图同步回收，关闭后的迟到结果立即释放。长时间使用不会因累计访问超过 96 个不同图标永久停止加载。

实现：`native/RemoteIconCache.cs`、`native/Program.cs`。原生侧栏离线回归覆盖容量、并发、失败恢复、淘汰及关闭释放，并通过实际侧栏接线检查关联着色图回收。

## 6. 参考统计来源跨英雄保留冷却

`RecommendationRepository` 保留一个延迟初始化的默认参考来源及其初始化 promise，避免每次刷新重新创建读取器。OP.GG 401/403/429 后的 30 分钟冷却因此跨英雄、仓库重试和并发初始化保留；不会在普通 ARAM 被阻止时改走排位来源。不同仓库实例的冷却独立。

注入的参考客户端保持原样；现有时钟、英雄、版本、来源与 24 小时新鲜度守卫继续适用。离线回归拦截全部外部请求，覆盖 60 秒后仍无新请求、29:59.999 仍被阻止、30 分钟整恢复请求及实例隔离。

实现：`server/recommendation-repository.mjs`。回归入口：`tests/recommendation-repository.test.mjs`、`tests/reference-build-source.test.mjs`。
