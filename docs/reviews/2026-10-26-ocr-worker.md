# 1.13.0 OCR 优化与独立复查记录

日期：2026-10-26。基线：`be485bde0d74b5406a129b5785a43c2669611769`；初次实现：`141aadf4fc2387a36e73b0fda81f17c7175d90dc`；问题修正：`3d063c2d5828f1773d503da49f1cc95f9b53841b`。

## 实现

- 保留 Windows OCR，通过按需启动的本地工作进程复用运行时、语言和引擎，逐任务重置画面、身份锚点和计时。
- 三个彩色标题先识别；现有匹配器确认三个标题与锚点完整后，跳过不必要的增强对比和全画面处理。未通过则保留完整回退。
- 每个请求仍捕获新帧，阶段认可后仍须最终前台验证；原有局次、轮次、采集资格与人工纠正守卫保留。候选不等于已选，六格面板确认阈值不变。
- 工作进程只接受有界控制消息；单任务超时、退出、损坏输出或未结束的 OCR 操作会清理或撤销该进程，不重试旧帧。关闭扫描器先终止自有进程再等待后台清理。
- 诊断仅增加有界初始化、采集、识别、总耗时和运行时复用标记；没有新增屏幕、原始文本、玩家身份或凭据存储。

## 复查循环

按 `requesting-code-review` 的模板分别派发两个独立审查者，只提供需求、基线和待审提交；审查为只读，不继承实现过程的完整会话，不再分派审查子代理。

| 第一轮发现 | 修正与验证 |
| --- | --- |
| 原生 ConvertFrom-Json 会折叠重复控制字段，绕过严格协议校验（Important） | 在转换前进行有界控制语法和解码字段名唯一性检查，包含 Unicode 转义的重复键；保留字段换序和合法安全整数。 |
| 固定待审提交缺少原生阶段与故障边界测试（Important） | 加入实际生成画面的 3/6/7 次处理、空白回退、缺答复、未完成操作取消和普通失败回退；增加原生协议字节上限、损坏、EOF、UTF-8、重复键及 ACK 测试。 |
| Node JSON.parse 同样会折叠重复外层字段（Minor） | 在使用消息版本和请求 ID 前核对外层字段唯一性，正确区别嵌套内容、转义字符串和重复字段。 |
