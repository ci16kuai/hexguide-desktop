# 1.13.1 重复侧栏修复记录

日期：2026-10-26。源码基线：`6ed10a6`。

## 已验证原因

用户反馈 Ctrl＋左键拖动后再使用 Alt＋Shift＋H 收放，有时出现两个面板。只读进程及窗口元数据确认现场存在两个 1.13.0 桌面实例，各有独立的主窗口、侧栏、快捷键接收器、实例接收器和本地后台服务；两者实例接收器身份相同。快捷键诊断记录 Windows 错误 1409，表示组合已被占用。

两份进程的 `--data-dir` 参数均为 `%LOCALAPPDATA%\HexGuide\data`。读取进程现有锁句柄的最终文件路径后，确认一份实际落到 Codex 的打包应用 `LocalCache\Local\HexGuide\data`，另一份落到普通用户 `AppData\Local\HexGuide\data`。Windows 打包应用的 AppData 重定向将相同文字路径分成两个物理文件，因此各自文件锁都能取得。安装版与已核对构建的 EXE 摘要一致，不是旧版缺少文件锁。优化构建的强制 GC 夹具也未复现租约被提前释放。

Ctrl 拖动和快捷键只操作既有侧栏。两个侧栏重叠时看似一个，移动其中一个后会露出另一个；两套程序也会独立切换可见状态。这是已观察到的重复进程问题，不归因于拖动创建窗口。

## 修复边界

在启动界面、后台服务与快捷键之前，按规范化逻辑目录取得当前 Windows 会话内的命名互斥保护，并保留原有物理目录文件租约。两种来源即使被重定向到不同文件，仍共享逻辑目录互斥身份。普通重复打开仍只请求已有窗口恢复；不同数据目录保留独立运行能力。资源在失败和退出时释放，已有数据不迁移。
