# 海克斯文字识别调度（1.11.4 测试版）

## 开局和复活窗口

重文字识别只在加载结束进入实战，或可信的自身死亡→存活变化后启动一个识别周期。周期前 60 秒以 500 毫秒为目标开始间隔；一分钟后若仍未确认新海克斯，进入 `follow-up` 阶段，以 5,000 毫秒为目标继续扫描，直到实际选择经过统一确认边界记录。死亡也结束旧周期，下次可信复活重新开始快速阶段。普通战斗、等级变化、已有候选和准备状态均不能自行启动新周期或重置前一分钟。

加载时不扫海克斯文本，阵容与装备预览仍由本机游戏接口提供。首次接入时若游戏时间在第一分钟内，只补余下快速阶段时间，之后仍未确认则转入慢速阶段；中后期首次读取“存活”不冒充复活。重复、乱序、过期、未来或跨局快照不能触发新周期。`DEFAULT_OCR_SCHEDULE_POLICY` 保留有界的快速阶段时长、快慢间隔、冷却和失败退避配置，供后续扩展。

500 毫秒和 5,000 毫秒都是开始时间目标，不是完成频率保证。单次 OCR 仍按需启动，超过目标耗时就等待结束，再至少休息 100 毫秒，不重叠、不排队补扫。引擎错误退避 5/10/20/30 秒，失焦退避 5 秒，不把快速阶段顺延；失焦时不捕获游戏或其他应用画面。手动扫描可在周期外执行，复用已有在途任务。快慢切换属于同一周期，在途任务可以有界结束；已确认、死亡或切换到新周期后，旧自动任务的迟到候选不会重开周期或取代新轮次。

## 自身生命状态

`server/collector.mjs` 只提取唯一匹配自身玩家的 Live Client `isDead` 布尔字段。缺失、异常或身份不确定返回 unavailable，不根据生命值、其他玩家或第一行记录猜测。模型的 `life` 明确区分 `live-client`、`screen` 和 `unavailable`。接口有效时始终优先。

屏幕备用功能分三层：纯 `ScreenLifeObserver` 状态机、`ScreenLifeController` 采集调度、`ScreenLifeSource` 后端边界。接口缺失时才考虑备用；只检查已验证的前台游戏，不切屏、不操作游戏。便宜的三个局部颜色采样先决定是否需要读取计时器；需要 OCR 时，三个场景与头像复活倒计时从同一内存画面裁剪，不把不同时刻的颜色和文字拼成证据。

死亡要求至少三帧、跨度至少一秒的灰度变化及实际递减、符合时间变化的 1–180 秒倒计时。单次变暗、静止数字、Tab 面板、未知 OCR 均不能证明死亡。复活要求此前已验证死亡，随后连续恢复彩色且两次计时 OCR 都确认空白；失败不是“计时消失”。焦点、客户区、DPI 或局次变化，以及采样间隔过长均清除旧证据。该保守策略可能漏识别，不能用来推断已选海克斯。

屏幕证明只包含固定八字段，经过本地 token、Host、Origin、局次、时间单调和稳定帧校验。屏幕状态 3 秒过期，死亡历史最多保留 10 秒供复活核对；明确失焦通知清除历史。API 恢复即取代屏幕状态。图像与 OCR 原文不落盘、不上传。

## 屏幕校准与当前限制

没有真实死亡/复活样本时，默认返回 `experimental-calibration-required`，不启用猜测的位置。校准文件位于当前个人数据目录 `screen-life-calibration.json`，最多 4 KiB，必须与当前游戏客户区宽高及 DPI 完全一致。结构为 `version:1`、`verified:true`、`clientWidth / clientHeight / dpi`、一个 `timer` 矩形以及恰好三个 `scene` 矩形；矩形包含客户区相对物理像素 `x / y / width / height`，场景另有经实测的 `aliveSaturation` 基线。

各位置必须由同一布局真实死活画面校准；`verified` 不可替代实机审查。其他应用覆盖游戏客户区时，完整计时采集停止；仅验证为同一安装路径的助手进程可作为可信覆盖层。即使是助手，遮住任一计时或场景采样区域也拒绝采集；校准区域应避开侧栏。当前仅支持已校准、前台且采样区域无遮挡的布局。

## 自动确认与诊断

本模块只决定何时扫描卡片，不决定玩家选了什么。Native 原有鼠标边沿、选择特效和选后核对窗口保持独立节奏；慢速续扫不会延长这些证据的有效期限。OCR 三个候选不等于已选；确认来源仍通过同一会话边界更新装备和后续海克斯建议，技能强化图标不能算作已选。

`ocr.schedule` 固定输出 `mode / due / intervalMs / nextInMs / windowRemainingMs / trigger / windowId`。快速阶段为 `window`，慢速续扫阶段为 `follow-up`；`windowRemainingMs` 仅表示快速阶段剩余时间，归零不代表识别周期结束。`windowId` 跨越同一周期的快慢阶段保持一致，只有新的开局或可信复活周期才分配新值。`diagnostics/ocr-schedule.json` 保持 schemaVersion 2，单份小于 2 KiB，额外包含程序版本、更新时间、扫描/失败次数及最近耗时；不含身份、局次、候选、图片或凭据。同档普通更新最多约 5 秒落盘一次，模式、周期或扫描次数改变可立即写入；单个最新待写快照，原子替换，失败不影响识别。

1.11.3 真实对局已验证接口识别死亡、复活后启动扫描以及旧规则的一分钟到期停扫。自动确认仍未通过：“伤不过三”没有自动记录，后续保留卡片时也曾未显示“已就绪”。1.11.4 本次只修正一分钟后的扫描调度，不宣称选择特效、自动记录或确认后的推荐更新已修复。

离线验证只能证明事件调度与边界行为，不能证明屏幕备用的准确率、实际资源节省或自动确认已通过实战。当前运行的旧助手不受源码修改影响，新版需另行更新；新版慢速续扫、自动选择记录和随后的推荐变化仍需真实对局验收。
