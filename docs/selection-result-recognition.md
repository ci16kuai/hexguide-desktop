# 选后海克斯结果识别设计记录

## 1.17.2：亮色槽位定位与推荐顺序推定（2026-10-27）

现场六格面板含有亮色插画及品质边框，旧定位器要求每格至少 60% 暗色采样，导致整块面板被拒绝。改为检查六格边界内外的颜色变化，并保留金色外框、蓝色间隔及完整布局要求；结构有效的候选网格再通过本轮三候选及已选图标的严格匹配校准位置。相似度 0.90 和异形分差 0.065 门槛不变，不用全库搜索或放低门槛补猜。

按用户本次要求，只有证据已证明本轮完整同图标组时，才按与三选一显示相同的推荐顺序默认推定其中较推荐者。排序包含当前英雄、已确认海克斯、路线、可信统计及机制回退；只在匹配组内选择，无法推荐的组仍待确认。旧轮使用自己的三候选；不同图标的模糊近似不进入此推定。保留“推定已选（同图标）”及手动纠正；旧 `inferredChoices` 持久化保持兼容，通用标签也不把历史统计推定误述成新算法。

现场只读校准探针连续 12 帧定位且匹配一个已记录模板，相似度约 0.975、定位 34–47 ms；没有在真实会话提交选中记录。完整“新候选→选择→已选栏→自动记录”仍待实战验收。详情见[本次诊断记录](reviews/2026-10-27-panel-recovery.md)。

## 1.16.1 当前源码：死亡时仍核对已选栏（2026-10-27）

被动面板确认使用独立的当前游戏资格，不再继承点击观察的死亡/死亡后生命未知限制。死亡、复活和明确丢失采集资格仍撤销旧凭据，之后需要至少三个新帧；原始对局快照过期、暂停、断连、未知模式、换局或缺少有效候选锚点时继续等待。候选文字、鼠标点击或面板出现均不能单独成为已选结果。诊断 schema v2 增加固定采集阶段与累计计数，当前等待状态不再覆盖最后一次实际读取的阶段；不新增图像、原始文字或身份信息。现场定位及模板可读性检查与完整自动记录验收分别记录，见[修正记录](reviews/2026-10-27-panel-confirmation.md)。

## 1.15.0 当前源码：保留未确认轮次（2026-10-26）

最新未确认三卡保留在主要区域，旧轮显示待确认；死亡、暂停及临时断连撤销短时点击/面板证据，不丢弃逻辑候选，也不以 60 秒或五分钟放弃。恢复后使用新凭据、至少三个新帧和现有窗口/字形校验继续被动核对用户已打开的面板；多轮有停留时间地轮换，跨轮相同候选无法归属时仍待确认。确认绑定具体轮次，较晚轮先记录也不清空旧轮，后补记录保持原顺序。候选目录与顺序可持久化，采集描述、标题锚点和窗口信息不持久化。实现与验证边界见[待确认保留记录](reviews/2026-10-26-pending-offers.md)。

## 1.12.1 历史源码：玩家打开六格面板核对（2026-10-25）

本节说明本次测试版源码的新行为，取代下文旧版“尚未接入结果采集”及必须依赖选前点击凭据的现状描述；旧记录保留其原有日期与实验边界。**此前实战记录对应 1.11.3，本次没有切屏、安装或重启助手与游戏；新版尚未经过连续真实对局验收。**

玩家在游戏内选择海克斯，然后自己打开英雄头像左侧的六格强化符文面板。`OwnedPanelWatcher` 只在游戏前台、原客户区几何仍匹配且所需区域无遮挡时被动观察；不按 Tab、不打开面板、不移动鼠标、不代选。需要此前通过同帧完整标题锚点识别出本轮有序三个候选；仅有名字草稿、助手卡片、无锚点结果或全库相似图标均不能启动确认。

主要原生自动路线使用独立的面板来源 `panel-icon`：旧选择卡片标题不再可见后，定位六格 HUD 面板，限定本轮候选的游戏素材核对图标，并要求至少三个不同采集帧、稳定布局及一致槽位分类。后端同时校验帧间隔、时效、当前局次、修订、候选顺序和轮次 token。它不伪造旧 `provider:screen` 的鼠标点击或选择特效；旧动画观察、`OwnedAugmentVerifier` 与对应夹具保留用于历史回归。有面板核对资格时，不再以旧动画提交作为主要自动路线。

1.12.1 统一原生与服务端的字形身份：面板证明升级为 **v2**，固定包含 `version / provider / offerToken / gameId / gameEpoch / revision / ids / glyphs / frames` 九个顶层字段。`glyphs` 使用 `normalized28-sha256-v1`，为当前三个候选及最多六个已选模板附带有序的 ID/URL 绑定摘要和归一化字形摘要。服务端按摘要核对整个同形组，允许不同 URL 的真实相同字形，扣除已有同形图标的出现次数；同 URL 的矛盾身份、错序、缺项、修改目录绑定或超过 4 KiB 的证明均拒绝。近似字形不会升级成精确同形组。摘要是原生分类证明，不是后端独立像素校验；不写入会话或诊断，也不上传。

候选建议在 60 秒后可以从界面过期，面板核对资格独立保留至**最近一次有效卡片采集后最多五分钟**，供玩家选完后打开。持续读到同轮完整卡片可以刷新时效；卡片消失后不再延长，普通空白或失败扫描不能续期。重抽、换局、暂停、手动改选或修订变化撤销旧资格。已记录的同图标海克斯需要额外出现一次才构成新结果，不根据填充格数推算轮次。没有本轮候选上下文时不扫描全库补猜历史选择；面板关闭、遮挡、未知图标、多个不明新增结果或证据不稳定均保持待核对，不清空已选列表。

可信死亡立即更新识别生命周期并撤销旧候选、点击/特效凭据及面板资格；可信复活再开启新周期。新采集不得使用生命周期开始前的旧帧，即使候选 ID 与上次完全相同也必须获得新 token。普通未知生命状态或失焦不冒充死亡，也不续期。手动与自动调用可共享同一次在途 OCR，其完成结果使用相同的生命周期、局次、修订和当前资格守卫；同一周期的快速→慢速切换不会误拒绝结果。详见[六项修复记录](reviews/2026-10-25-six-fixes.md)。

1.12.1 的历史同图标处理如下（1.17.2 已按本次要求改为共享推荐顺序，见本文顶部）：

- 先证明对应的是本轮候选中**完整的同图标组**；低分近似、不同素材的模糊匹配不会进入统计猜选。
- 使用当前英雄、海克斯大乱斗模式与当前版本的真实聚合使用场次 `sampleCount` 优先。场次可能包含同一玩家的多局，**不是去重玩家人数**，不显示为精确人数。
- 默认把最高使用场次的 90% 及以上视作接近，在此组内选胜率最高者；使用场次相差较大时不被更高胜率反转。精确并列、缺少必要统计或不匹配英雄/模式/版本时继续等待手动确认。
- 统计区分的选择以**“推定已选（同图标统计）”**保存和展示，可在完整助手移除并改选。它说明助手采用的推定，不证明游戏实际选择了该海克斯；手动纠正优先。

技能强化仍按可选随机事件处理：不能固定跳过首格，不能把全部 `IsAbilityAugment` 定义排除。未知或已提供排除模板的图标不按填充格计入正常已选；本次尚无经过核实的额外技能固定图标素材，因此不声称已确定该图标的具体 ID，或所有与候选同形的情况均已可靠排除。

首个 HUD 定位配置来自用户提供的原始 **2559×1440** 附件；离线定位与“渴血”图标模板比较取得约 **0.953** 的相似度。这只证明该附件的定位及一次模板比较，不是识别准确率，不证明关闭面板、技能强化、其他 HUD 比例、DPI 或分辨率都可可靠识别。新来源的会话保护、统计推定、重放拒绝、持久化和推荐重算有隔离测试；实际选择→打开面板→自动记录→装备和后续推荐更新仍需下一次真实测试。

所有成功来源仍调用同一确认与推荐重算边界。载荷仅含有限分类、采集时间及上下文守卫，图像与模板特征在本机内存中处理，不保存截图、原始 OCR 或玩家身份。开局与复活的文字扫描规则见[扫描调度](ocr-scheduling.md)：首个可用开局实战快照给予完整一分钟快速阶段，未知时钟不提前消耗开局机会；之后未确认则每五秒继续。

## 1.10.3 及此前研究记录（历史）

当时状态：1.10.3 已实现标题身份门控、点击特效续接和独立选后图标证据核心；结果面板的自动采集与该核心尚未接入当时运行中的确认流程。2026-10-24。

## 目标与证据优先级

优先观察游戏中玩家已经获得的海克斯，确认实际结果，再更新助手。选择动画、鼠标位置和卡片消失只能辅助判断时机，不能代替结果身份。

优先级为：经过本机实测的局中已选数据 → 游戏自身已选栏的明确结果 → 保留现有手动确认。助手自己的候选卡片、“本局已选”或推荐界面不能作为游戏已选结果的证据。

## 1.10.3 修复及当前验收边界

- 同帧 OCR 现在为完整标题行建立紧框字形特征；PS 与原生采样共用 `CardTitleIdentity.cs` 的亮度归一化 Sobel 实现，支持两行标题。缺锚、混帧、混 pass 或不完整文字覆盖仍只显示候选，不授权自动输入观察。
- 前选身份核对不再要求整卡 RGB 不变。标题短暂不可读只暂停输入资格、保留本轮；真实按下仍须三标题全部匹配、游戏前台、几何和无遮挡校验。换局、换卡、人工修改和过期仍撤销。
- 放开卡身变色后，收起判定也必须分离：使用真实松键帧作三卡 RGB 对照，并要求三个标题全部不再匹配。已有 hover 颜色差、单张亮化或仅一个标题丢失均不能当作三卡收起。现有自动提交仍要求真实点击、独立特效与至少三帧收起证据。
- 并发 OCR 的暂时空白/失败不再立即抹掉此前已发生的点击；冻结凭据仅供原点击在原 2.5 秒特效时限内完成，不能据此开始新点击。相同候选恢复不会覆盖旧点击凭据；前台丢失、不同候选、暂停、换局及人工修改仍硬撤销。
- `OwnedAugmentVerifier` 是纯内存视觉证据核心：本轮三候选、可选已知排除模板、选前基线、至少三个独立选后帧和真实游戏 down/up lease 一致才输出 `VerifiedCandidate`，之后仍须统一会话边界复核。无选前基线、未知同形、候选碰撞或无真实点击只保留不确定；它不直接写 owned。
- 用户已确认：**4.0 的技能强化是随机事件，其他对局可以没有；本赛季其图标固定。** 因此不能假设每局都有、固定跳过首格或根据填充格数计轮。固定图标应放在版本化排除模板中；不能把全部 `IsAbilityAugment` 定义排除。
- 只读标题探针在一轮真实三选一上取得 52 次有效采样：三标题 52 次全部匹配，新状态 51 帧就绪，而旧整卡门槛会拒绝 39 帧。该实验验证本次画面的身份门控，不包含真实点击、选择提交或推荐更新验收。旧包装器省略了提前停止原因，不能声称完整连续观察了八秒。
- 用户自然打开 Tab 后，只读取得的一帧 2560×1440 画面在内存中用于定位研究。旧均值边线评分会把图标强边当作格线；改为逐段连续覆盖后定位到实际 3×2 槽位附近。此单帧定位未证明跨分辨率、关闭面板、遮挡和多人布局都可靠，尚不启用自动结果采集。

只读探针默认不采集，显式授权开关、PE 版本及无 UI 自测能力标记同时满足后才可运行；不启动助手 UI、后端、输入或会话写入。研究画面不存盘，日志仅有有界计数、状态和几何研究数字。

## 已验证的事实

- 早先三张照片（完整游戏三选一、ChatGPT 遮挡游戏中央、悟空助手侧栏近照）没有提供可绑定到游戏自身已选槽位的完整选后样本。后续两张手机照片同时展示了属性面板与 Tab 结果面板，已用于人工标注和离线对照；助手画面可读不等于游戏结果可自动可靠读出。
- 根据最新用户说明，第一张选后照片的两个图标分别是**额外技能强化（具体 ID 未确认）**与普通海克斯**杀戮时间到了**（`its_killing_time`）；第二张照片保留这两者，并新增**渴血**（`goredrink`），共三个图标。不能把两个初始图标都称为技能强化，也不能把填充槽数当成普通已选海克斯数量。
- 本地 `dist/data.json` 当前有 244 个常规可推荐定义，只有 202 个不同的 `icon` URL。21 组共 63 个定义共享 URL；即使把品质一并作为键，仍有 20 组共 60 个定义共享 URL 和品质。
- 例如“尤里卡”和“大法师”共享同一棱彩图标；“面包和黄油”“面包和奶酪”“面包和果酱”等属于 14 个定义共用通用图标的一组。不同 URL 也可能包含相同或近似像素，因此 URL 不重复仍不能证明图像唯一。
- 数据更新脚本从客户端定义的 `AugmentSmallIconPath` 填充当前 `icon`。助手还会对素材进行品质着色；不能直接把助手着色后的图像当成游戏 HUD 模板。
- 手机照片离线实验另加入四个仅头牌发放、不可常规推荐的定义（力量、厄运、鞭挞、重型）；它们共用一个新增 URL，所以实验口径为 **248 个定义 / 203 个不同 URL**，区别于常规池的 **244 / 202**。这不表示照片中的额外技能强化已经识别为这四者之一。
- 已讨论样例“暴击律动 / 循环往复 / 更万用的瞄准镜”的三个素材 URL 不同，可作为限定三候选的实验对象，但其选后 HUD 显示方式和缩小后的可区分性尚未实测。
- 当前 collector 只在响应确实存在 `own.augments` 或 `activePlayer.augments`，且所有 ID 都能精确映射时返回 detected；没有拿符文代替海克斯。这个条件分支不证明真实游戏提供这些字段，sidebar 也没有把它自动写入 owned。
- 最新本机探测已使用官方 CA 取得接口响应：本局取得的响应未提供 `augments`，`fullRunes` 为 `{}`，另有 HTTP 204 无正文响应。这些是本次对局与已探测路径的事实，不是“所有局中接口都没有海克斯数据”的结论；空符文对象或无正文也不等于零个已选海克斯。
- 混格说明影响未来的选后面板识别，不是本次漏记的已证实原因。1.10.2 日志已确认 `frame-preclick-mae-close` 在 `pressed=false`、`edgeColumn=-1`、`ready=true` 时取消了整卡 RGB 前选校验；这与光标移动时观察到的画面变化相关，但尚未像素级定位到 hover、边框或其他区域，不能归因于面板格数。

## 用户已确认的显示条件

以下入口已由用户说明，并在后续两张手机照片中同时出现；照片对照尚不构成自动识别验收：

- **入口 1：属性面板。** 用户通常用它查看属性，不会经常打开；不能假定它始终展开或始终可读。该入口的完整名称、工具提示和槽位表现仍需样本核对。
- **入口 2：玩家按 Tab 打开的游戏大面板。** 用户确认这里只有海克斯图标，没有名称。它不是长期可见区域，不能把 Tab 面板当成持续可读的名称来源。

本次照片中的槽位可以人工按两行三列标注；其中混有额外技能强化和普通海克斯。技能强化的类别由用户确认，具体 ID 未确认。不能按英文 `Ability Augment` 标签统一排除：本地 KIWI 定义中也有普通可选海克斯带 `IsAbilityAugment:true`。

后续只能在玩家自行打开这些入口、且结果区域确实可见时被动识别，不自动按 Tab、不切换面板、不移动鼠标或主动悬停。面板关闭或遮挡时保持“暂不可读”，不推断零个海克斯，也不删除已经确认的选择。入口 2 仍须满足本轮候选内图标唯一、稳定新增槽位等结果证据；图标歧义不能靠猜测消除。

## 尚未知晓，不能提前宣称支持

- 两个入口的自动定位锚点、跨分辨率的槽位几何和稳定变化规则；本次照片的人工两行三列标注不能直接当作实时坐标。入口 1 的完整名称是否可见、是否需要玩家自然悬停仍待验证。入口 2 只有图标，不能假设有可直接 OCR 的名称。
- HUD 比例、分辨率、Windows DPI、品质颜色、透明背景、遮挡和游戏版本变化对模板匹配的影响。
- 升阶、质变、任务进化、额外海克斯及替换型效果，是否修改旧槽位、增加槽位或更换图标。不能把每个图标变化都当成新增海克斯。
- 是否还有受支持的局中接口或事件可覆盖本模式的已选信息。本次已取得响应但未取得可用的已选字段，不代表其他路径、版本或模式均无接口。

## 已有照片的离线模板实验

实验只使用上述两张手机照片、人工面板边界与用户标签；未实现或启用 observer，没有独立实时对局验收。24 个相关槽位对照中，21 个可评分，另 3 个因裁切缺失不能比较，不能称为 24 个独立游戏样本。

Tab 区域的目标模板有较高相似度，但全库排名存在近同形歧义：

| 照片与目标 | 203 个不同 URL 中的排名 | 与最佳其他模板的分差 |
| --- | --- | --- |
| 第一张：杀戮时间到了 | 1 | +0.00001 |
| 第二张：杀戮时间到了 | 3 | -0.00004 |
| 第二张：渴血 | 1 | +0.00004 |

例如“杀戮时间到了”与 `final_form`、`surge_field` 的模板得分几乎相同；“渴血”也与其他 URL 的模板近乎并列。全库 top-1、不同 URL 或较高相似度均不足以自动确认。HUD 区域的裁切、透视与画质更差，目标模板排名明显不稳定；即使某个目标槽位覆盖完整，也不能据此声称 HUD 自动可可靠读取。

按用户告知的金色/银色筛选后的排名只用于离线评估，尚未实现或验证自动颜色分类，不能把用户品质标签当作识别器已经获得的输入。本实验也未评估限定本轮三个候选后的区分性；手工透视校正和多尺度配准可能对这些照片过拟合，尚无可用于实战确认的阈值或准确率结论。

## 最小可验证的屏幕路线

第一阶段只在已经可信识别出本轮三个候选时验证选后结果，暂不扫描全库猜测任意海克斯。

1. 先用真实选后样本确认玩家当前已打开的游戏结果入口、锚点和槽位语义，明确区别于普通增益图标、敌方信息和助手侧栏；不为采集结果自动打开任何面板。
2. 在同一游戏、同一轮候选和同一套物理窗口几何下，记录可见槽位的状态，仅保留内存中的有限特征。普通海克斯、额外技能强化和未知格分开处理，不由槽数反推已选轮数。
3. 选择后跨多个独立帧观察：旧槽位保持可解释，新增结果确实属于本轮三个普通候选之一，并排除技能强化等异质格变化。单纯恰好新增一个稳定槽位仍不证明选中了普通海克斯；卡片消失只表示可以开始寻找结果。
4. 图标证据不足时，等待玩家自然显示的游戏名称文字，使用完整标题精确 OCR，并绑定到同一结果槽位或工具提示。不得从聊天、战斗文字或助手画面抽取名称。
5. 不能确认唯一结果时保持“未确认”，提供原有手动入口。

两类候选证据需要分别验证：

- **新增槽位与图标**：实际已选栏出现稳定新增槽位；图标在本轮三个候选中唯一；多个独立帧一致。全库共用图标不一定妨碍限定三候选，但同一轮三候选中有重复或无法区分的图标时必须拒绝自动确认。
- **选后名称文字**：玩家自然显示了已选结果的完整名称；OCR 精确匹配当前候选之一，结果区域身份和游戏上下文也匹配。单个模糊字符、描述中出现名字、悬停尚未选择的候选卡片都不足以确认。

匹配分数高、品质颜色相同、鼠标最后所在列、英雄属性变化或推荐排序，都不能单独成为结果身份。多槽位同时变化、无法解释的替换、已有海克斯再次出现及截取不完整时，一律保留不确定状态。先取得真实样本验证，再确定阈值和所需帧数。

研究和后续实现不自动移动鼠标、悬停、按 Tab 或替玩家选择。早期照片分析仅使用用户附件；本次用户自行打开面板和三选一后新增了只读内存采样，未切屏或重启游戏、助手。单独的助手更新和标题门控实验都不构成新结果 observer 已通过实战验证。

## 数据来源的边界

[Riot Live Client Data API](https://developer.riotgames.com/docs/lol#game-client-api_live-client-data-api) 是局中本机接口，官方示例包含英雄属性、技能、符文等信息；已查看的文档没有给出可直接依赖的 Mayhem 已选海克斯字段。必须以获准的实际模式响应验证，不能把字段缺失当成零个海克斯。

[Overwolf LoL augments 文档](https://dev.overwolf.com/ow-native/live-game-data-gep/supported-games/league-of-legends/#augments) 明确区分三候选 `augments` 与最后选中的 `picked_augment`。这是此前研究的另一种局中结果来源；用户已于 **2026-10-25** 决定停止推进 Overwolf 路线，以下相关资格和事件说明仅作为历史研究记录，不再列入后续实施计划。当前以独立 EXE 的本机客户端同步、候选 OCR 和玩家手动打开六格面板后的图标核对为主；历史文档示例不能视为成功接入或实际已选证据。

LCU 局后战绩或公开 Match API 中的字段，即使能回溯选择，也不能自动视为局中实时接口。开源应用声称能记录局后选择同样不能直接证明其支持当前对局中的实时确认。

公开参考及复用边界：

- [Sygnano/aram-mayhem-tracker](https://github.com/Sygnano/aram-mayhem-tracker/tree/7c28471bf5b511e545d8d1c38b63707157edb134)：可参考按钮 ROI、卡框边缘门控与多分辨率测试；它跟踪展示过的 `seen`，不确认实际已选。
- [zp96-cmd/mayhem-overlay](https://github.com/zp96-cmd/mayhem-overlay/tree/57c23850cc67c7b3394666ea62f5a1ebe02d0641)：确有更新已选列表的链路，但依据最近悬停与卡片消失推测；这不能替代游戏结果证据，相关误确认风险不应直接继承。
- [英雄联盟官方公告（2026-06-22）](https://lol.qq.com/news/detail.shtml?docid=7990353454630637480)：描述依据已选海克斯及双方阵容推荐，并支持海斗自定义；未提供第三方实时 SDK。公告 GIF 与用户视频样式相近，只能支持“可能为官方智能助手”的推断，不能确认视频产品身份或可复用接口。

以上为有限范围的公开资料核查，尚未找到经过源码验证、可直接复用到当前普通海克斯的完整选后 HUD 确认方案，不代表全网不存在其他实现。

## Provider-neutral 确认契约演进

现有 `provider:screen` 证据是“真实点击 + 独立反馈 + 卡片收起”的实验契约。新结果识别不得伪造 `uniqueFeedback:true` 来通过旧动画契约。

后续应分别验证并声明证据种类，例如 `screen-owned-slot-delta`、`screen-owned-title`、`authoritative-picked-augment`。它们可以共享最终的受守卫提交步骤，但拥有独立的严格输入结构、验证器、测试及可用状态。

第一阶段结果观察至少绑定：gameId、gameEpoch、expectedRevision、offerToken、本轮有序 candidateIds、唯一 selectedId、观察时间和对应证据种类。仅允许 selectedId 属于这一轮的候选；证据必须来自本游戏、当前可用结果区域，并在各自明确的时限内。截图、原始 OCR、玩家名和完整第三方事件不进入确认载荷或诊断文件。

必须保留：

- 游戏边界、暂停、断连、窗口几何或候选身份变化使旧观察失效；不能让新事件回填到上一局。
- revision 和 epoch 守卫阻止旧结果覆盖较新的手动纠正；手动修改优先。
- 同一轮/同一结果只提交一次，重复事件不重复追加；空快照、暂不可读及不完整槽位不清空 owned。
- 自动来源也通过共同的权威提交与推荐重算步骤，不直接整表覆盖 session。
- 对质变、替换、额外槽位和无候选上下文的权威快照，另行设计并测试恢复规则，不通过放宽第一阶段守卫顺带支持。

可先离线测试候选内碰撞、相似图标、槽位新增/消失、旧帧、换局、重复结果和手动纠正竞态。真实 HUD 样本和正反例不足时，observer 保持未实现/未启用状态，不能把模拟测试通过描述成实战识别成功。
